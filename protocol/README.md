## Reader Notes & Archive Key Mapping

- **Stage S1 vs. Secondary Estimands:** Frozen protocol text and `data/final_receipt.json` label secondary estimands `S1`–`S14`; the manuscript writes `SA1`–`SA14` so they do not collide visually with pipeline stages `S0`–`S5`.
- **Protocol §9 Conditional Native-Build Branch (`WP-P1`):** All 32 confirmatory Repository clusters entered Stage S0/S1 intake and stopped at Stage S1 under `no_independent_repository_spec` (`R = 0` route stops). Because the Contest execution lower bound exceeded the pilot upper bound (`27.2% > 15.5%`) with `R = 0 < 12`, §9's conditional native-repository build branch was not triggered; dynamic S2–S5 evaluation therefore covers standalone Contest submissions only.
- **Pre-Amendment-5 Diagnostic vs. Production Quarantine:** The 5-pair quarantined diagnostic (`m2-quarantined-diag-5.tar`, 2 executed) cited in Amendment 5 predated confirmatory S3 execution and is disjoint from the 204 production quarantined S1 passes marked `not_executed` at closure.
- **Protocol §10 & Upstream Receipt Custody:** `data/final-a5-stats-agg.json` (`9eebab8d...`), `data/author-check-50-agg.json` (`4f84a8ef...`), and `data/alert-and-fit-forensics-agg.json` (`b8ea9b8c...`) remain strictly byte-frozen with their original offline schema keys (including `section10_substitution`, documenting owner-approved SHA-pinning before P1–P3 in lieu of a git commit, plus archival keys such as `camera_ready_checks`, `owner_terminal`, `preregistered_*`, and `devin_workflow_mode: null`).
